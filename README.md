# 长护险预评估与收入分层养老服务匹配 App

## 项目简介

本项目是一个面向银行杯/金融创新创意比赛的养老金融服务方案展示网页。基于大陆长期护理保险制度基础，借鉴台湾长照服务评估与分层匹配经验，构建"长护险预评估 + 补充照护服务匹配 + 收入分层推荐"的可落地养老服务 App 方案。

**最终定位**：帮助老人和子女在真正失能之前，就能看见风险、理解政策、算清预算、匹配服务。

## 技术栈

- **框架**：React 18 + TypeScript
- **构建工具**：Vite 6
- **样式**：Tailwind CSS 3
- **字体**：Google Fonts (Noto Sans SC)

## 预评估评分逻辑

- 日常生活能力：轻度受限 +2，中度受限 +4，重度受限 +7
- 认知能力：偶尔遗忘 +1，明显下降 +3，需要专人看护 +6
- 行动能力：拐杖辅助 +2，他人搀扶 +4，长期卧床 +7
- 风险因素：独居 +1，子女不同城 +1，年龄 ≥80 +1

**结果分类**：
- ≥10 分：A 类 — 可能符合长护险申请条件（蓝色）
- 4-9 分：B 类 — 暂未达到门槛但存在照护需求（橙色）
- <4 分：C 类 — 基本自理，仅需预防性服务（绿色）

## 适老化设计特点

- 字号不小于 17px（手机端 15px）
- 高对比度配色，暖色调为主
- 图标直观，按钮大且有明显圆角
- 卡片层次清晰，带轻微阴影
- 响应式布局适配手机、平板、电脑
- 所有评估结果均标注"不代替正式评定"

## 比赛展示讲解重点

1. **痛点切入**：当前长护险制度偏向重度失能支付，轻中度需求覆盖不足
2. **两岸经验结合**：大陆制度基础 + 台湾评估匹配经验
3. **创新逻辑**：评估 → 分流 → 测算 → 推荐 → 持续管理
4. **服务对象创新**：覆盖"未达门槛但已有需求"的群体
5. **金融服务创新**：保险保障 + 支付管理 + 服务匹配 + 风险预防
6. **可落地性**：基于现有制度框架，不做颠覆式改造

## 服务升级版功能

### 交互式服务详情弹窗
点击八、推荐服务内容中的任一服务卡片，弹出详情弹窗，包含三个标签页：
- **服务详情**：完整介绍、适合人群、具体服务项目、费用参考、支付建议、风险提示、服务提供方类型、标签
- **附近推荐**：基于服务类型的附近服务提供方推荐，包含模拟地图、评分排序、长护险/补贴支持标识
- **预约服务**：模拟预约表单，提交后展示服务闭环流程

### 用户信息绑定（localStorage）
- 右下角悬浮 👤 按钮打开绑定面板
- 支持姓名、年龄、电话、地址、紧急联系人、居住情况、长护险状态、照护需求、既往病史
- 所有信息仅保存在浏览器本地，不上传服务器
- 支持编辑和删除

### Mock 地图 UI
- 基于经纬度的模拟地图展示服务提供方位置
- 支持高德地图 API 接入（配置 VITE_AMAP_KEY）
- Provider 信息含距离、评分、联系方式、支持长护险/补贴标识

### 服务闭环流程图
- 需求发现 → 政策匹配 → 预算测算 → 服务匹配 → 预约对接 → 服务落地 → 动态调整
- 桌面端横向展示，移动端纵向时间线

### API 集成预留面板
- 可折叠的 API 设计方案面板
- 用户端 API（5个端点）、机构端 API（3个端点）、管理端 API（3个端点）
- 包含技术栈建议（JWT、PostgreSQL、Redis、高德地图）
